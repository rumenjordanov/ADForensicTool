ADForensicTool improvement plan
================================

Work happens on the `improvements` branch. After each step: run the test
suite + ruff, exercise the change by hand (CLI / generated report), fix
anything found, commit, then move on. Push to GitHub at the end.

Status legend: [ ] todo   [x] done   [-] skipped (reason given)

STEP 1  Packaging   (done)
  [x] Move code into an `adforensictool/` package (parser, rules, correlator,
      narrator, excel_export, console, version, cli) so installing it no
      longer drops top-level `parser`/`rules`/`console`/`main` modules into
      site-packages.
  [x] Keep `python main.py ...` working via a thin root shim.
  [x] Ship default_rules.yaml as package data; single version source
      (pyproject reads adforensictool/version.py dynamically).
  [x] CI: add ruff lint + pytest-cov coverage.

STEP 2  Excel formula injection
  [ ] Escape any string cell value starting with = + - @ \t \r (prefix ')
      in every place report.py writes log-derived text.
  [ ] Regression test with a hostile username.

STEP 3  Correct actor fields per event ID   (done)
  [x] Per-event-ID field mapping: `user` = account the event is about
      (4728/4732/4756 -> the MEMBER added, not the group), new columns
      `subject_user` (who performed it) and `target_group`.
  [x] Parse <UserData> as well as <EventData> (real 1102 events keep
      SubjectUserName under UserData/LogFileCleared).
  [x] Also: `user_sid` column (MemberName is a CN/display name, so SIDs are
      the reliable join key), "-" / NULL SID treated as absent, DN -> CN.
  [x] Tests.

STEP 4  Parse statistics   (done)
  [x] Count records read / skipped (malformed); show in CLI and on the
      Executive Summary (high skip counts = possible tampering).

STEP 5  Rule engine hardening + generic conditions   (done)
  [x] Flagged events sorted by timestamp (found in step 4 E2E run: rows
      came out grouped by rule, not chronological).
  [x] Validate rules: unknown keys, severity values, duplicate ids, required
      fields, bad regex, circular/unknown `after` refs -> RuleError naming
      the rule. CLI now loads rules BEFORE parsing the log (fail fast) and
      reports RuleError cleanly; warns on an empty rule set.
  [x] `match:` (AND list) and `exclude:` conditions on any rule type, with
      equals / contains / startswith / endswith / regex, case-insensitive,
      hex-normalized equals; {all: [...]} groups in exclude. Old
      `field`/`equals` form keeps working.
  [x] Kerberoasting: exclude krbtgt, machine ($) services and requesters,
      and failed requests (Status != 0x0).
  [x] Bug found while probing: events with no timestamp (NaT) were swept into
      whatever threshold cluster was open. Fixed + regression test.

STEP 6  New rule capabilities   (done)
  [x] threshold: `distinct_field` + `min_distinct`; group_by keys compare
      account names case/domain-insensitively (jsmith == CONTOSO\JSmith).
  [x] New `followed_by` rule type (after, within_minutes, join_on), rules
      auto-ordered so dependencies run first.

STEP 7  New detections (YAML)   (done)
  [x] password spraying, successful logon after brute force, AS-REP
      roasting (4768 PreAuthType 0), DCSync (4662 replication GUIDs by a
      non-machine account), account created (4720), scheduled task (4698),
      service installed (4697 / 7045), audit policy weakened (4719 removals
      only), DSRM password set (4794), account lockout (4740), pass-the-hash
      style logon (4624 LogonType 9 seclogo), persistence after suspicious
      logon (followed_by with new join_on_later: logon user -> subject_user).
  [x] MITRE names for all referenced techniques. Tests for each (+/-).
  [x] Found: Kerberos events log IPs as ::ffff:a.b.c.d, NTLM as a.b.c.d ->
      spraying across both protocols was split. Normalized in the parser.
  [x] Found via 200k-event perf probe: pd.to_datetime per record was 87% of
      parse time. fromisoformat fast path: 64s -> 9.4s, identical results.
      python-evtx's datetime.min (year 1) "no time" marker -> NaT.

STEP 8  Allowlist   (done)
  [x] `--allowlist file.yaml`: suppress flagged events by field conditions,
      optionally scoped to specific rule ids. Suppressed counts shown in CLI
      and on the Executive Summary. Runs after all rules, so allowlisted
      noise can't hide a follow-on compromise. Entries without conditions
      rejected; unknown rule ids in scopes warned about (typo guard).
      examples/allowlist.example.yaml added (validated by a test).

STEP 9  Correlator   (done)
  [x] build_chains: stages = threshold clusters / single events; identity =
      normalized users + SIDs + non-machine subject_user; source_ip only for
      stages with no account or several accounts (sprays); host never used.
      Stages sharing an identity within window_minutes are linked
      (transitively); components spanning >= 2 rules become chains.
      Each event belongs to at most one chain (answer to the open question:
      no double counting). Stages tagged with ATT&CK tactics.
  [x] Tests (16). Found two bugs while testing: fixtures gave every account
      the same SID, and machine accounts as an event's `user` (4698 by
      DC01$) linked routine events. Fixed both; regression test verified to
      fail without the fix.
  [x] Perf: 16k findings took 15s (per-stage DataFrames) -> 0.5s.

STEP 10 Narrator   (done)
  [x] Phrase builder per rule + generic fallback; works per stage so
      partial / unanticipated sequences narrate too (answer to the open
      question). Consecutive same-rule stages merged; an event flagged by
      two rules described once under the more severe one. Timezone aware;
      multi-day chains show dates. chain_headline() gives a short title.
  [x] Tests (10), including the exact sentence from the project spec.
      Caught while testing: multi-day prefix rendered as
      "2026-06-08 06-08 23:50-06-09 00:20" -> now "... 23:50 to 2026-06-09 00:20".

STEP 11 Report integration   (done)
  [x] Attack Chains tab: chain table + stage breakdown; per-rule grouping
      moved to its own "Detections by Rule" tab. Executive Summary: ATTACK
      NARRATIVE section, ATTACK CHAINS KPI tile. chain_id column on Raw
      Flagged Events. Times written as real Excel datetimes in the display
      timezone (tz param), zone named in headers. CLI prints chains,
      --chain-window option.
  [x] Visually verified by exporting through Excel to PDF -> PNG. Found and
      fixed: (a) all 3 charts rendered without axis labels/categories
      (openpyxl 3.1 omits <delete val="0"/>; pre-existing bug), (b) chain row
      cells bottom-aligned next to the wrapped narrative, (c) row-height
      estimate too conservative, (d) same account listed twice in chain
      headline ("jsmith and jsmith@CONTOSO.LOCAL"), (e) "→" crashing /
      garbling on cp1251 consoles -> console uses errors="replace" and "->".
      Regression tests for (a) and (d), verified to fail without the fix.
  [ ] (moved to step 12) banner source path overflows when long.

STEP 12 Input: multiple files / folders, faster parsing   (done)
  [x] `--input` accepts several files and/or directories (recursive *.evtx).
      `source_file` column; overlapping exports de-duplicated on
      channel + computer + EventRecordID (new record_id / channel columns).
  [x] Event-ID prefilter (cheap regex before XML parsing); --all-events
      turns it off. KPI now shows log records read.
  [x] `--backend auto|python|rust` (pyevtx-rs when importable).
      FOUND: pyevtx-rs ("evtx") and python-evtx ("Evtx") cannot coexist on
      Windows -- same directory on a case-insensitive FS; installing one
      breaks the other. So no pip extra; README documents a separate venv.
      Real-file comparison: identical normalized output except 1us float
      rounding; rust ~45x faster (22.7s -> 1.05s end to end).
  [x] FOUND (real corrupted .evtx): one bad record aborted the WHOLE parse
      (all 3458 good events lost). Now read chunk by chunk; losses counted
      exactly from chunk headers (3387 recovered, 71 lost).
  [x] NEW: EventRecordID gap analysis per file/channel/computer (deleted-
      record anti-forensics indicator; caught the 86 records the rust
      backend could not count). Shown in CLI + Executive Summary.
  [x] FOUND: Application log has unrelated Event ID 4625s (EventSystem
      provider); with directory input that means false positives (e.g. any
      app's 1102 = "audit log cleared"). Rules now have `channels`
      (default Security). Regression test verified.
  [x] Real-binary fixture tests/fixtures/empty.evtx (export matching no
      events; verified to contain no identifying data). Banner shows file
      names, not full paths (fixes overflow noted in step 11).

STEP 13 Output formats + timezone   (done)
  [x] `--format xlsx,json,csv,timeline` (timeline = Timesketch-compatible CSV,
      always UTC); default inferred from --output's extension; several
      formats are written side by side. JSON carries stats, record-ID gaps,
      allowlist counts, chains (narrative + stages) and all findings.
  [x] CSV formula-injection escaping (= + @ \t \r, and "-" unless a plain
      number) -- unit tested. Checked in real Excel via COM: .xlsx shows the
      hostile value as text with 0 formula cells (conclusive); for CSV the
      check was INCONCLUSIVE: an unescaped positive control did not evaluate
      either when opened through automation, so CSV relies on unit tests.
  [x] `--timezone` (IANA name) for all displayed times (report, console,
      CSV, JSON); tzdata declared for Windows.

STEP 14 Sigma import (subset)   (done)
  [x] `--sigma` files/dirs: windows security/system rules; field maps with
      list=OR, modifiers contains/startswith/endswith/re (+|all), * and ?
      wildcards; conditions `sel`, `not sel`, `all of x*`, `not 1 of x*`,
      `not (a or b)` joined by "and"; level/tags mapped. Everything else is
      skipped WITH a reason (e.g. SigmaHQ's own kerberoasting rule uses a
      list-of-maps filter -> rejected rather than approximated).
  [x] examples/sigma/: 3 original example rules (not copied from SigmaHQ,
      whose rules carry the DRL license), verified to convert and fire.
  [x] Found in E2E: event flagged by both a built-in and a Sigma rule of
      equal severity was narrated twice -> tie-break fixed (+ regression
      test verified to fail without the fix).
